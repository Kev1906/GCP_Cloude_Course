## 4. Tendencias del Mercado 2025-2026

### 4.1 Lo que Está Creciendo

#### **Lakehouse Architecture (Iceberg/Delta Lake)**
- **Demanda:** +85% YoY en job postings
- **Por qué:** Unifica data lake + data warehouse, reduce costos, soporta ACID
- **Empresas adoptando:** Netflix, Uber, Airbnb, LinkedIn, Databricks customers
- **Salario premium:** +15-20% vs roles tradicionales

#### **Data Quality & Observability**
- **Demanda:** +120% YoY
- **Herramientas:** Great Expectations, Soda, Monte Carlo, Metaplane, dbt tests
- **Por qué:** "Garbage in, garbage out" - las empresas están hartas de datos incorrectos
- **Rol emergente:** Data Reliability Engineer

#### **Streaming & Real-Time Processing**
- **Demanda:** +65% YoY
- **Herramientas:** Kafka, Flink, Spark Structured Streaming, ksqlDB
- **Por qué:** Fraud detection, personalización, IoT, real-time analytics
- **Salario premium:** +10-15% vs batch-only

#### **dbt (Data Build Tool)**
- **Demanda:** +95% YoY
- **Por qué:** Estándar de facto para transformaciones en analytics engineering
- **Empresas:** 80% de startups Serie B+ usan dbt
- **Rol:** Analytics Engineer (híbrido DE + Analyst)

#### **Data Governance & Catalog**
- **Demanda:** +75% YoY
- **Herramientas:** OpenMetadata, DataHub, Unity Catalog, Amundsen
- **Por qué:** GDPR, CCPA, compliance, data discovery
- **Rol emergente:** Data Governance Engineer

### 4.2 Lo que Está Estancado/Declinando

| Tecnología | Tendencia | Por qué |
|-----------|-----------|---------|
| **Hadoop** | 📉 Declinando | Reemplazado por cloud storage + Spark |
| **On-premise ETL** (Informatica, Talend) | 📉 Declinando | Migración a cloud-native |
| **ZooKeeper** (para Kafka) | 📉 Obsoleto | KRaft mode es el estándar |
| **Manual orchestration** (cron scripts) | 📉 Obsoleto | Airflow/Dagster/Prefect |
| **JSON-only schemas** | 📉 Declinando | Avro/Protobuf + Schema Registry |

### 4.3 Lo que Está Emergiendo (2026-2027)

#### **AI/ML Integration para Data Engineers**
- **Demanda:** +150% YoY (pero aún niche)
- **Skills:** Feature stores (Feast), model serving, MLflow
- **Por qué:** Los DEs están habilitando ML pipelines, no solo analytics
- **Rol:** ML Engineer / MLOps Engineer

#### **Data Mesh Architecture**
- **Demanda:** +45% YoY (empresas grandes)
- **Por qué:** Descentralización de data ownership
- **Empresas:** Fortune 500, enterprises con múltiples dominios

#### **FinOps & Cost Optimization**
- **Demanda:** +80% YoY
- **Por qué:** Cloud bills están explotando, empresas necesitan optimizar
- **Skill:** Query optimization, warehouse right-sizing, tiered storage

#### **Agentic AI & LLM Integration**
- **Demanda:** +200% YoY (pero muy nuevo)
- **Skills:** Vector databases, RAG pipelines, LLM orchestration
- **Por qué:** Empresas están integrando LLMs en sus productos
- **Rol emergente:** AI Engineer

## 8. Entrevistas: Qué Esperar

### Proceso Típico (Senior Data Engineer)

1. **Recruiter Screen** (30 min)
   - Background, expectativas salariales, disponibilidad

2. **Technical Phone Screen** (45-60 min)
   - SQL avanzado (window functions, CTEs, optimization)
   - Python (data structures, algorithms básico)
   - System design básico

3. **Take-Home Assignment** (3-7 días)
   - Diseñar y construir un pipeline ETL/ELT
   - Documentación, tests, diagrama de arquitectura
   - Presentación de 30 min al equipo

4. **Onsite Loop** (4-5 horas, 4-5 entrevistas)
   - **System Design:** Diseñar plataforma de datos a escala
   - **SQL Deep Dive:** Optimización, query planning
   - **Coding:** Python/Scala, data structures
   - **Behavioral:** Leadership, conflict resolution, mentoring
   - **Culture Fit:** Valores, colaboración, comunicación

5. **Offer** (1-2 semanas después)
   - Negociación de salario, RSUs, signing bonus

WITH RECURSIVE org_chart AS (
  SELECT employee_id, manager_id, name, 1 as level
  FROM employees WHERE manager_id IS NULL
  UNION ALL
  SELECT e.employee_id, e.manager_id, e.name, oc.level + 1
  FROM employees e JOIN org_chart oc ON e.manager_id = oc.employee_id
)
SELECT * FROM org_chart;
